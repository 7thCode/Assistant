GGUFファイルフォーマット

Assistantが読み込むモデルの形式です。パラメータ数や量子化タイプの読み方は モデルガイド を参照してください。

GGUF は、llama.cpp(ggml)系のエンジンで推論するためのモデル格納形式で、旧形式 GGML の後継です。重みだけでなく、トークナイザやチャットテンプレート、モデルの構造情報まで1つのファイルにまとまっています。llama.cpp・node-llama-cpp・Ollama・LM Studio などが読み込めます。

ファイルの構造

1. ヘッダ
マジックナンバー GGUF、バージョン(現行は v3)、テンソル数、メタデータ数。
2. メタデータ(Key-Value)
general.architecture(モデルの系統)、*.context_length、*.embedding_length、*.block_count、tokenizer.ggml.*(語彙・特殊トークン)、tokenizer.chat_template、general.file_type(量子化の種類)など。
3. テンソル情報
各テンソルの名前・形状・量子化タイプ・データ領域内のオフセット。
4. テンソルデータ
重み本体。アライメント(既定32バイト)されているため、mmap でそのままメモリに載せられ、読み込みが速くなります。

特徴

  • 1ファイルで完結: 重み・トークナイザ・チャットテンプレート・ハイパーパラメータが全て入っており、追加ファイルは不要です。
  • 拡張しやすいメタデータ: Key-Value 形式なので、項目を足しても互換性を保てます。Hugging Face もこのメタデータからパラメータ数などを表示しています。
  • テンソルごとに量子化タイプを変えられる: Q4_K_M が「4bit一色」ではなく、重要な層だけ Q6_K を混ぜた構成なのはこのためです。
  • 分割ファイル: 大きなモデルは model-00001-of-00003.gguf のように分割されます。llama.cpp では最初のファイルを指定すれば残りも自動で読み込まれます。
  • アダプタや埋め込みモデルも GGUF: Assistantで使う LoRA アダプタや RAG 用の埋め込みモデルも同じ形式です。
